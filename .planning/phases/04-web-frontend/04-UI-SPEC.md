| Label | 14px | 500 (medium) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |

**Notes:**
- Body (16px / 400 / 1.5): All chat message text, citation excerpt text, login form helper text.
- Label (14px / 500 / 1.4): Form field labels, citation card document title, button text, nav items.
- Heading (20px / 600 / 1.2): Login page title ("Sign in"), page-level section headings.
- Caption (12px / 400 / 1.4): Citation card collapsed preview (~50-char excerpt), timestamp if added, secondary meta.
- Only 2 weights are used: 400 and 600. Weight 500 is used only for labels (shadcn default; collapses to 600 if constrained).

## Component Interaction Contracts

### Login Page (`/login`)

**Layout:** Centered card on full-height white background. Card width: 400px max. Vertically centered via flexbox.

**Form fields:**
- Username input: `type="text"` autocomplete="username"
- Password input: `type="password"` autocomplete="current-password"
- Submit button: full-width, text "Sign In"

**States:**
- Default: empty fields, enabled submit button
- Loading (after submit): button shows spinner icon + "Signing in..." text, fields disabled
- Error (401 from `/auth/login`): inline error message below form — "Invalid username or password. Please try again." — rendered in `text-destructive` (red). No toast.
- Network error: "Unable to connect. Check your connection and try again."

**Redirect behavior:** On successful login, navigate to `/` (chat). An unauthenticated visit to `/` redirects to `/login`. Source: CONTEXT.md D-12.

---

### Chat Page (`/` or `/chat`)

**Layout:** Single-column, full-width. No sidebar. Source: CONTEXT.md D-01.

Sub-regions top to bottom:
1. **Header bar** — fixed top, full width, height 56px. Contains app title left-aligned ("Privacy Policy Assistant") and "Log out" button right-aligned.
2. **Message list** — scrollable, takes remaining vertical space. Overflow-y: auto. Scroll-to-bottom on new message.
3. **Input row** — fixed bottom, full width, height 52px. Contains text input (flex-grow) and "Send" button.

**Message bubbles:**
- User message: right-aligned, `bg-zinc-100`, `rounded-lg`, `px-4 py-3`, `max-w-[70%]`
- Assistant message: left-aligned, white background, `border border-zinc-200`, `rounded-lg`, `px-4 py-3`, `max-w-[80%]`

---

### Streaming Response (UI-03)

- While streaming: append `|` cursor character to end of growing text. Cursor blinks at 1s interval via CSS `animate-pulse` or `@keyframes blink`.
- On `done` event: remove cursor, render final text, then fade in citation cards.
- Source: CONTEXT.md D-03.

**SSE implementation:** Must use `fetch` + `ReadableStream` — NOT `EventSource`. Reason: `/api/chat` requires `Authorization: Bearer <token>` header which `EventSource` does not support. Source: CONTEXT.md Specifics section.

**Event types from backend:**
- `delta` event: `{type: "delta", content: "token"}` — append to streaming buffer
- `done` event: `{type: "done", answer: "...", citations: [{id, title, text}]}` — replace buffer with final answer, render citations
- `error` event: `{type: "error", detail: "..."}` — show inline error message

---

### Citation Cards (UI-04 / CITE-04)

**Collapsed state (default):**
- Rendered below assistant message text, after `done` event fires
- Appears via fade-in: CSS `opacity 0 → 1` transition over 200ms. Source: CONTEXT.md D-04.
- Shows: lucide `FileText` icon + document `title` as primary label + first ~50 chars of `text` with ellipsis as secondary line
- Chevron icon (lucide `ChevronDown`) right-aligned to indicate expandability
- Background: `bg-zinc-50 border border-zinc-200 rounded-md`

**Expanded state (on click):**
- Chevron rotates 180deg (CSS transform transition 150ms)
- Full `citations[N].text` verbatim excerpt shown below the title
- Text in `font-mono text-sm` to visually distinguish as a verbatim legal quote
- Background: `bg-white border border-zinc-300 rounded-md`

**Multiple citations:** Stack vertically with `gap-2` between cards. No tabs, no carousel.

Source: CONTEXT.md D-05, D-06, D-07.

---

### "No Matching Policy Found" State (UI-05)

Triggered when backend returns RAG-07 path (no chunks above 0.55 threshold).

**Display:** Inline within the message list, styled as an assistant message bubble but with distinct visual treatment:
- lucide `AlertCircle` icon in `text-amber-500`, 20px
- Heading: "No matching policy found" in `font-medium`
- Body: "The query did not match any passages in the indexed policy corpus. Try rephrasing your question or using different terms."
- No citation cards below this message.

---

### Logout (UI-06)

- Button label: "Log out" (not "Logout" — two words per standard English)
- Location: header bar, right-aligned
- On click: POST `/auth/logout` → clear `localStorage` (access_token, refresh_token) → navigate to `/login`
- No confirmation dialog — logout is not a destructive data action
- Source: CONTEXT.md D-11

---

### Token Refresh (Silent)

- On HTTP 401 from `/api/chat`: attempt `POST /auth/refresh` with stored refresh_token
- On success: store new access_token in `localStorage`, retry original request once
- On 401 from refresh: clear both tokens, redirect to `/login`
- Must track "already-retried" state to prevent infinite loops
- Source: CONTEXT.md D-09, D-10

## Routing Contract

| Route | Authenticated | Unauthenticated |
|-------|--------------|-----------------|
| `/` or `/chat` | Show chat interface | Redirect to `/login` |
| `/login` | Redirect to `/chat` | Show login form |

Implementation: React Router v6 with a `ProtectedRoute` wrapper that checks `localStorage` for access_token. If absent, renders `<Navigate to="/login" replace />`.

---

## API Integration Contract

| Endpoint | Method | Auth header | Body | Response |
|----------|--------|------------|------|----------|
| `/auth/login` | POST | None | `{username, password}` JSON | `{access_token, refresh_token, token_type}` |
| `/auth/refresh` | POST | None | `{refresh_token}` JSON | `{access_token, token_type}` |
| `/auth/logout` | POST | Bearer token | None | `{}` |
| `/api/chat` | POST | Bearer token | `{message, history}` JSON | SSE stream |

**Vite dev proxy:** Configure `vite.config.ts` to proxy `/api` and `/auth` to `http://localhost:8000` during development. This avoids CORS and mirrors Docker Compose nginx routing.

**Fetch library:** Use plain `fetch` API for all calls (auth endpoints and SSE). No axios, no React Query in Phase 4 — keep dependencies minimal for a greenfield SPA. The SSE stream requires a custom `ReadableStream` parser that extracts `data:` lines and JSON-parses each event.

## Animation Contract

| Interaction | Animation | Duration | Easing |
|-------------|-----------|----------|--------|
| Citation cards appear after `done` | opacity 0 → 1 | 200ms | ease-out |
| Citation card expand/collapse chevron | rotate 0 → 180deg | 150ms | ease-in-out |
| Streaming cursor blink | opacity 1 → 0 → 1 | 1000ms | step-end (CSS `animate-pulse`) |
| Login loading spinner | continuous rotation | 800ms | linear |

No other animations. Keep motion minimal — compliance tool, not a marketing site.

## Accessibility Contract

- All interactive elements meet WCAG 2.1 AA contrast ratio (4.5:1 for text, 3:1 for UI components)
- All form inputs have associated `<label>` elements (not placeholder-only)
- Keyboard navigation: tab order follows visual order; submit on Enter in chat input
- `aria-label` on icon-only buttons (e.g., send button if icon-only)
- Citation card uses Radix `Collapsible` — keyboard accessible by default
- Focus ring visible on all interactive elements (shadcn default ring style)
- No motion-only communication — streaming progress conveyed by text cursor, not animation alone
