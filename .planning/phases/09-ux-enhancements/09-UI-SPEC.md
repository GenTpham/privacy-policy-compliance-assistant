## Design System

| Property | Value |
|----------|-------|
| Tool | Radix UI + Tailwind CSS (no shadcn components.json — components exist as hand-authored primitives) |
| Preset | none — project uses dual-system approach: Tailwind zinc classes (chat primitives) + inline theme tokens (AppShell screens) |
| Component library | Radix UI (collapsible, form, label) — direct imports via `radix-ui` package |
| Icon library | lucide-react |
| Font | Inter (system fallback stack: Inter, ui-sans-serif, system-ui, sans-serif) |
| Theme system | `frontend/src/lib/theme.ts` — `ThemeTokens` interface + `makeTokens(isDark)` + `useTheme()` hook |

**Existing UI architecture note:** Two parallel styling systems exist in this codebase.
- **Chat primitives** (`ChatPage`, `Header`, `MessageBubble`, `CitationCard`, `ChatInput`): Tailwind zinc class utilities, light-mode only.
- **App shell screens** (`AppShell`, `AskAssistantScreen`, `DashboardScreen`, etc.): inline style objects using `useTheme()` tokens, supports dark/light toggle.

Phase 9 features (source filter dropdown + retrieval score display) live inside `AskAssistantScreen`. They MUST use the inline theme token system (`useTheme()`) to match the existing screen, not Tailwind classes.

**No new component libraries required.** No third-party shadcn registries.

## Component Interaction Contracts

### Feature 1: Source Filter Dropdown / Sidebar

#### Current state (Phase 8 baseline)
`AskAssistantScreen` already renders a left sidebar with filter buttons sourced from `POLICIES` in `mockData.ts`. The active filter state (`activeFilter`) is stored in local `useState`. However:
- The filter is purely cosmetic — it does not affect the `submit()` call to `/api/chat`.
- Policy list is mock data (`POLICIES` array), not fetched from the backend.

#### Phase 9 requirement
The source filter MUST actually scope the backend query. Two sub-tasks:

**Sub-task A: Real source list from backend**
- Add `GET /api/sources` endpoint (backend) — returns `string[]` of distinct `title` values from the Qdrant collection.
- On `AskAssistantScreen` mount: fetch `/api/sources` with auth header. Store in local state as `sources: string[]`.
- Prepend the fixed option `"All Sources"` at index 0.
- While loading: show skeleton rows (3 placeholder lines, same height as filter buttons, `t.border` background).
- On fetch error: show inline error text — "Could not load sources. Try refreshing the page." — in `t.faint` color, 12px. Keep "All Sources" as the only selectable option.

**Sub-task B: Pass source filter to backend**
- `ChatRequest` body gains optional field: `source_filter?: string | null`
- When `activeFilter === "All Sources"`: send `source_filter: null` (backend applies no payload filter)
- When `activeFilter` is a policy title string: send `source_filter: "Google Privacy Policy"` (exact `title` string from Qdrant payload)
- Backend must apply Qdrant `must` condition on `payload.title == source_filter` when non-null

**Sidebar layout (no change from existing):**
```
width: 220px
borderRight: 1px solid t.border
background: t.surface2
```

**Filter button states:**

| State | Background | Text color | Font weight |
|-------|------------|------------|-------------|
| Inactive | transparent | t.text3 | 400 |
| Active | accent | #ffffff | 600 |
| Hover (inactive) | t.surface (t.surface + 10% darker) | t.text | 400 |
| Disabled (no sources loaded) | transparent | t.faint | 400 |

Filter buttons are `<button>` elements. No dropdown overlay — the existing left sidebar is the filter UI. Do NOT convert to a `<select>` element.

**Section label format (no change from existing):**
```
fontSize: 12
fontWeight: 600
color: t.faint
letterSpacing: "0.06em"
textTransform: "uppercase"
marginBottom: 10
```

**Source name display:** Strip " Privacy Policy" and " Privacy Statement" suffixes from title for display (existing logic in `AskAssistantScreen` — keep). Show full title as `title` attribute on the button for accessibility.

**Active filter indicator in chat header:** The chat column header already shows `activeFilter` (stripped) next to "Ask Assistant". Keep this. When "All Sources" is active, show "All Sources" (no strip needed).

### Feature 2: Retrieval Score Display on Citation Cards

#### Where it lives
Scores appear in the **Evidence panel** (right sidebar, 300px wide) in `AskAssistantScreen`. The Evidence panel already shows citation cards from `activeEvidence` state. Each card already has a `ConfidenceBar` with a hardcoded `score={0.85}` — this must be replaced with the real score from the backend.

The score also appears inline in the **citation card collapsed row** in the chat message area (the `msg.citations` block inside the message bubble).

#### Backend change: add `score` to Citation model
```typescript
// Current Citation interface (useSSEChat.ts)
export interface Citation {
  id: number;
  qdrant_id: string;
  title: string;
  text: string;
}

// Phase 9 — add score field
export interface Citation {
  id: number;
  qdrant_id: string;
  title: string;
  text: string;
  score: number;  // cosine similarity from Qdrant, 4 decimal places max
}
```

Backend `rag.py` must include `score: round(chunk.score, 4)` in each citation dict. The `done` event JSON gains this field.

#### Score display: Evidence panel (right sidebar)
Replace the hardcoded `<ConfidenceBar score={0.85} />` with the real citation score. The existing `ConfidenceBar` component already implements the semantic traffic-light coloring. Use it.

Display format in Evidence panel (per existing card layout):
```
[Relevance label]  [ConfidenceBar with real score]  [numeric "0.38"]
```
The numeric value is rendered as `score.toFixed(2)` (2 decimal places) — e.g. "0.38", "0.32", "0.44". Font: 12px / 600 / semantic traffic-light color.

#### Score display: Chat message citation card (collapsed row)
In the chat message area, each citation card shows a compact score badge on the right side of the collapsed trigger row, between the preview text and the ChevronDown icon.

```
[FileText icon]  [title / preview]     [score badge]  [ChevronDown]
```

Score badge format:
- Container: inline-flex, border-radius 4px, padding 4px 8px
- Background: 15% opacity of the semantic traffic-light color
- Text: `score.toFixed(2)`, 12px, 600, semantic traffic-light color

Example rendered output for score=0.38: `0.38` in `#EF4444` on `rgba(239,68,68,0.12)` background.

Do NOT show a `ConfidenceBar` in the chat message citation card collapsed row — the badge format only. The bar is reserved for the Evidence panel.

**Score display: expanded citation card state** — No score display in the expanded body. Score is only shown in collapsed row and Evidence panel. Verbatim text occupies the expanded area, not score metadata.

### Interaction: Source Filter + Retrieval Score Combined

When a user selects a source filter AND submits a query:
1. `source_filter` is sent in the chat request body
2. Backend applies payload filter — only chunks from that policy are retrieved
3. All returned scores are from the filtered set — they may be lower than unfiltered scores (fewer candidates)
4. Score display behavior is unchanged — show the actual cosine score regardless of filter state
5. No "filtered" indicator is added to the score badge — the active filter button in the sidebar provides that context

## API Integration Contract

### New endpoint: `GET /api/sources`

| Property | Value |
|----------|-------|
| Method | GET |
| Auth | Bearer token (same as `/api/chat`) |
| Path | `/api/sources` |
| Response | `{"sources": ["Google Privacy Policy", "OpenAI Privacy Policy", ...]}` |
| Error | HTTP 500 `{"detail": "Failed to retrieve source list"}` |
| Empty | `{"sources": []}` — frontend renders "No policies indexed." |

Implementation note: Query Qdrant for all distinct `payload.title` values. Use `scroll()` or facets if supported by qdrant-client 1.17.1. Return sorted alphabetically.

### Modified endpoint: `POST /api/chat`

New optional field in request body:

```typescript
{
  message: string,
  history: HistoryItem[],
  source_filter?: string | null  // null or absent = all sources
}
```

No change to SSE event format. The `done` event gains the `score` field per citation:

```json
{
  "type": "done",
  "answer": "...",
  "citations": [
    {
      "id": 1,
      "qdrant_id": "uuid...",
      "title": "Google Privacy Policy",
      "text": "...",
      "score": 0.3841
    }
  ]
}
```

## Accessibility Contract

Inherited from Phase 4 plus Phase 9 additions:

- Score badge: `aria-label="Retrieval score: {score}"` + `title="Cosine similarity: {score.toFixed(4)}"` — screen reader announces the value, sighted users see tooltip on hover
- Source filter buttons: `title="{full policy title}"` on each button (for truncated display names)
- "All Sources" button: no additional aria attributes needed — label is self-describing
- Skeleton rows: `aria-busy="true"` on the filter section container while loading
- `/api/sources` error state: rendered as visible text (not toast), `role="alert"` on the error container so screen readers announce it
- Source filter section: wrap in a `<nav aria-label="Policy source filter">` or equivalent landmark

WCAG 2.1 AA contrast requirements:
- Score badge text on badge background: traffic-light colors at full opacity on 15% opacity background. Verify: `#EF4444` on `rgba(239,68,68,0.12)` over `t.surface` = approximately 4.6:1 on light theme. Acceptable.
- Filter button active state: `#ffffff` text on `accent` (#6D94C5) background = 2.4:1. **This is a pre-existing contrast failure in the codebase.** Do not make it worse. Flag to developer: the active filter button fails AA contrast. Recommended fix: darken accent to `#3B72B0` for button backgrounds, which reaches 4.5:1 with white text. This is at developer's discretion; do not block Phase 9 on it.
