# Dashboard Real Data Implementation Design

## Purpose
To replace static mock data in the Dashboard with real data generated by the system, tracking user queries, popular topics, and document ingestion status.

## Architecture & Database Schema
Uses the existing SQLAlchemy setup (SQLite for dev, PostgreSQL for prod).

### 1. `query_logs` Table
- `id` (Integer, Primary Key)
- `user_id` (Integer, Foreign Key to `users.id`)
- `query_text` (String): The original question from the user.
- `topic` (String): Categorized topic of the query.
- `status` (String): Status of the response (`processing`, `success`, `error`).
- `created_at` (DateTime): Timestamp of the query.

### 2. `documents` Table
- `id` (Integer, Primary Key)
- `title` (String): Document title/filename.
- `chunk_count` (Integer): Number of chunks ingested. Default 0.
- `status` (String): Ingestion status (`Pending`, `Processing`, `Completed`, `Failed`).
- `created_at` (DateTime)
- `updated_at` (DateTime)

## Data Flow & Backend Modifications
1. **Topic Classification**: Add a utility function `classify_topic(query: str) -> str` using keyword/regex matching to assign categories (e.g., "Data Retention", "Cookies", "Third-Party Sharing") or "Other".
2. **Chat Endpoint (`POST /api/chat`)**:
   - Classify the query topic.
   - Insert a new `query_logs` record with `status='processing'`.
   - Update status to `success` or `error` at the end of the SSE stream.
3. **Ingestion Process**:
   - When document processing starts, create/update a `documents` record with `status='Processing'`.
   - On success, update `chunk_count` and `status='Completed'`.
   - On error, update `status='Failed'`.
4. **Dashboard API (`GET /api/dashboard/metrics`)**:
   - Query both tables to compute and return:
     - `totalPolicies`: Count of documents in `documents`.
     - `indexedChunks`: Sum of `chunk_count` across all documents.
     - `queriesToday`: Count of `query_logs` today.
     - `topTopics`: Group `query_logs` by `topic`, order by count descending.
     - `recentQueries`: List of latest `query_logs` entries.
     - `ingestionStatuses`: List of documents with their chunk counts and statuses.

## Frontend Modifications
1. Remove `mockData.ts` usage in `DashboardScreen.tsx`.
2. Implement a data fetch (using `fetchWithAuth`) to call `/api/dashboard/metrics`.
3. Add a loading state (skeleton/spinner) while data is being fetched.
4. Render the returned payload into the existing KPI cards, Recent Queries list, Top Topics bar chart, and Policy Ingestion Status list.

## Error Handling
- If the `/api/dashboard/metrics` call fails, display an error message gracefully on the dashboard instead of breaking the entire app shell.
- If inserting into `query_logs` fails during a chat, log the error but do not disrupt the LLM streaming response.

## Scope & Constraints
- Only the Dashboard is being migrated to real data in this phase. (Audit Log and Policy Library screens will be addressed in future phases).
- Vector store (Qdrant) logic remains completely unchanged.
- No LLM calls used for topic classification to keep response times low and avoid extra costs.
